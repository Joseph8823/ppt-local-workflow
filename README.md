# ppt-local-workflow

一个面向 Codex 的本机可编辑 PowerPoint 工作流 skill：**开场说明流程 → 确认整体框架与主要内容 → 确认样板图 → 确认逐页文字 → 确认完整 HTML → 提前提醒并操作本机 PowerPoint → 检查、保存和交付**。

它把重复的软件操作交给代理，把内容、风格和关键取舍留给使用者。支持从已有文稿、确认版 HTML/图片页面、已有可编辑演示文稿等不同阶段开始。

## 新建 PPT 的必经流程

开始就向使用者说明下面的步骤，重点提醒：**请亲自查看 AI 生成的内容和图片，发现事实、措辞、结构或图片含义有问题时及时提出，在本机制作前修正。** 生成完成和代理自检通过，都不能替代使用者确认。

1. **先确认整体框架和主要内容。** 展示整套 PPT 的页数、页面顺序、标题、核心要点和结论。使用者确认后，才能开始生成样板图或其他页面图片。
2. **生成真实样板图并确认风格。** 让使用者看到实际效果，判断是否需要调整。只有文字风格描述或一个模板文件不够；有模板时按模板生成对应样板，避免擅自重新设计。
3. **确认逐页文字。** 展示各页标题、正文、标签、数字、单位和必要引用。已经随框架完整确认的文字直接沿用；样板风格通过不代表新写的文字也通过。
4. **强制提供完整 HTML 总览。** 把全部页面汇入一份可离线查看的 HTML，让使用者检查全貌并明确确认。即使任务没有点名 HTML，新建整套 PPT 也要提供；少数样图或不完整预览无法替代。
5. **提前提醒，再操作电脑制作。** 完成上述确认后，在第一次控制本机应用或调用文档自动化接口前，说明接下来会操作 PowerPoint、制作和检查可编辑版本并按约定保存。已有授权时直接继续执行，无需重复索取许可。

逐页文字可以提前与整体框架一起确认。各关口等待使用者实际回复；沉默、文件已生成或早先的一句“继续完成”，都不能替代对尚未展示内容的确认。局部修订只更新受影响内容，保留其余确认。

## 适用任务

- 根据材料组织逐页内容，确认文案与图片含义。
- 按确认的整体框架生成样板图，再按确认的文字形成全套页面，强制汇入一份离线 HTML 供完整审阅。
- 将确认版页面重建成可编辑的本机 PowerPoint，或按要求仅交付结构化 SVG。
- 检查 SVG 插入和“转换为形状”后的字体、换行、位置及对象拆分。
- 直接修正已有演示文稿中的排版问题，保存为可继续编辑的副本。

## 核心约定

1. **直接完成本机操作。** 代理负责插入、转换、排版、检查、保存和重新打开文件，避免把这些步骤重新交给用户。
2. **沿用已有确认，补齐缺失环节。** 完整确认版 HTML 可以复用对应的框架、文字和风格确认；只有图片确认时，仍需补齐 HTML 总览。已确认可编辑稿的局部修改无需重新策划整套内容。
3. **代表页确定风格，完整 HTML 确认全貌。** 样板通过后自主完成全套页面，再集中请使用者确认完整 HTML，不默认逐张索取批准。
4. **按真实应用验收。** 浏览器效果、SVG 源码和静态检查不能代替本机 PowerPoint 的编辑画布检查。
5. **保持真实的可编辑粒度。** 文字和常用图形可编辑，复杂原图按完整图片保留；不把整页截图或逐字拆框称为完整可编辑重建。
6. **集中说明差异。** 修正影响使用的问题，避免反复打磨已经可用的小细节；剩余限制如实列出。

## 确认 HTML 后：结构化 SVG 重建与双态验收

当任务要求结构化 SVG，或选择 SVG 作为可编辑重建的中间方式时，必须执行这套规范。按确认版 HTML 和提供的模板逐页重建，保留内容与版式；任务只要 SVG 时，交付范围保持 SVG。明确禁止生成 PPTX 时，使用未保存的临时演示文稿做原生测试，不另存测试或最终 PPTX。

- **每个模板重新实测。** 读取实际 `PageSetup.SlideWidth/SlideHeight`、最终插入位置与宽高，记录 SVG viewBox 的映射比例。同为 16:9 不能沿用其他模板的结果。
- **文字和图片保持正确粒度。** 标题、标签或正文视觉行使用完整原生 `text`，明确字体、字号、字重、颜色和坐标；不逐字拆框、转轮廓或图片化。使用目标系统已有常见字体，不依赖额外字体、插件、网络字体或外部 CSS。每幅原图保留为完整内嵌 `image`，背景、边框和分隔线使用少量原生形状。
- **HTML、插入态、转形态三方对照。** 在目标 PowerPoint 中以最终方式插入，复制为相同页面与插入矩形，再执行“转换为形状”。两态取消选中后逐页查看编辑画布，并导出同分辨率预览。两态彼此接近，也必须接近确认版 HTML。
- **检查可见文字和边界，不能只看坐标。** 核对字高、整行宽度、字距、基线、换行、行距、段间距、右边界、图片位置及所有溢出和重叠。区分源锚点、字形范围、原生文本边界和形状框；插入态读不到逐行原生 TextFrame 时，须明确标注，不能伪造边界测量。
- **补偿必须写回 SVG 并复测。** 改成 pt、改根尺寸或增加缩放都只是待验证方案；不得通过移动、拉伸或替换临时 PPT 中的转形对象掩盖源文件问题。字高和整行宽度差异尽量控制在 5% 内，文字起点及基线偏差尽量控制在页面相应尺寸的 1% 内；任何文字不得越界或发生非预期重叠。
- **交付报告实际结果。** 每页报告转形后的文本框、完整图片和其他形状数量，以及剩余差异、缺失检查和跨设备字体替换风险。正文逐字成框、原图碎裂不能算通过。多行文字优先保持稳定和可编辑；纯 SVG 无法稳定得到整段单一原生 TextFrame 时必须明说。最终目录中的 SVG 还要重新插入，确认图片仍可显示。

完整执行细节见 [PowerPoint 与 SVG 规范](skills/ppt-local-workflow/references/powerpoint-and-svg.md)，证据记录见 [验收报告规范](skills/ppt-local-workflow/references/acceptance-report.md)。浏览器、SVG 查看器、源码和结构检查都不能替代上述原生验证。

## 安装与使用

将 [`skills/ppt-local-workflow`](skills/ppt-local-workflow) 整个文件夹复制到 Codex 的技能目录。已设置 `CODEX_HOME` 时，该目录为 `$CODEX_HOME/skills`；具体加载方式以所用客户端为准。技能本身不含安装器，也不修改 Office 或系统配置。

按需调用，例如：

```text
使用 $ppt-local-workflow。我要制作一份课程汇报 PPT，请先说明流程，
先给我确认整体框架和主要内容，再生成样板图。逐页文字和完整 HTML
都要让我审阅确认；操作本机 PowerPoint 前提醒我，最后交付可编辑副本。
```

```text
使用 $ppt-local-workflow。这里的完整 HTML 中，框架、文字和全部页面
效果已确认，请沿用；提前提醒后，在本机 PowerPoint 中重建可编辑稿，
检查后另存为一份我能继续修改的文件。
```

```text
使用 $ppt-local-workflow。以我确认的 HTML 和提供的 PPT 模板为准，
本轮只交付 SVG；在本机 PowerPoint 中检查插入态与转换为形状后的效果。
```

如果只需修改已确认可编辑稿的一页，直接说明修改范围、文件和保存要求即可；代理会简短提醒本次操作，再检查受影响页面，无需重新走整套设计确认。

## 环境与能力边界

- 技能是供代理执行的工作说明，**不包含通用的一键 PPT 生成器或自动点击引擎**。需要代理环境提供可用的本机应用控制或文档接口。
- PowerPoint 实测需要目标设备上的真实 PowerPoint。访问不到时，可以完成允许的准备工作，但必须把本机验证标为待完成。
- 新建整套 PPT 必须展示样板图和完整 HTML。需要环境具备生图或其他可用的非桌面预览渲染能力；无法提供时应明确说明缺失能力，不能静默跳过或提前控制本机应用绕过。已有明确确认的完整 HTML 可直接复用。
- 不捆绑 Office、字体、插件、模板或第三方设计素材。跨设备字体替换、Office 版本变化及复杂 SVG 特性都可能影响转换。
- 多行 SVG 文字可能转换成多个原生文本框，不承诺整个段落必定只有一个 TextFrame。

## 检查工具与开发验证

辅助工具只依赖 Python 标准库：

```text
python skills/ppt-local-workflow/scripts/audit_svg.py ./work/svg --output ./work/svg-audit.json
python -m unittest discover -s tests -v
```

结构检查包括原生文字属性、逐字坐标列表、图片内嵌、外部引用等。它不会启动 PowerPoint，也不会验证字形大小、基线、原图真实性、转形后的对象数量或实际可编辑性。结果中的本机视觉验证状态始终为未执行。

实际制作时，仍需代理在本机 PowerPoint 中逐页检查；SVG 转形须在相同插入矩形下比较两种状态，并将修正写回源文件。

## 开源内容范围

仓库只含通用流程、原创说明、辅助代码和虚构测试。没有实际用户的演示文稿、页面图片、校徽、研究材料、聊天记录、截图、个人资料或本机绝对路径。

使用此技能时，请将任务输入、生成文件和应用检查记录放在仓库以外的项目目录。`.gitignore` 是减少误提交的辅助措施，不能替代发布前对实际文件和 Git 历史的检查。不要把私人任务目录整体复制或提交到这个仓库。
